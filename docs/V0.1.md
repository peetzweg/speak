# speak v0.1: notes

Built 2026-11-19 from the Rust spike. **[M]** = measured here, **[I]** = inferred (read in code or
docs, not exercised). Machine: Apple M5 Pro, macOS 27.0.1, Rust 1.95.0, warm page cache.

## What works

- say-compatible CLI: text args, stdin, `-f FILE|-`, `-v`, `-v '?'`, `-r WPM`, `--speed`, `-o`, `-m`,
  say's other flags accepted and ignored (`-i` only takes a value with `=`, so it never eats the
  text). Usage errors are one `speak: …` line, exit 2. Exit codes 0/1/2/3/4 as in the spike. [M]
- Playback starts after the first sentence; synthesis runs ahead on a thread. [M]
- `-o`: WAV natively; other extensions via ffmpeg, or afconvert on macOS for .aiff/.aifc/.caf/.m4a;
  a missing converter fails before any synthesis. [M]
- English G2P: user lexicon → normalisation (versions, ISO and slash dates, clock times, `#N`,
  units glued to numbers, spaced capitals) → misaki-rs → `espeak-ng` subprocess for unknown words,
  converted with misaki's `EspeakFallback` table. Without espeak-ng, unknown words are spelled out
  with a one-line note. [M]
- Other languages (es, fr, hi, it, pt-br, ja, zh): espeak-ng for everything, converted the way
  Kokoro's own pipeline does (misaki `EspeakG2P`: tied diphthongs → `I W A O Q Y …`). [M]
- `--g2p espeak` (hidden): kokoro-onnx 0.4.7's exact path, kept for the regression test. [M]
- Lexicon commands and file identical to speak.py (`list` output is byte-identical on a copy of
  the real lexicon), plus `word = /phonemes/` entries validated against Kokoro's vocabulary, and
  `lexicon try` prints the phonemes it used. [M]
- Config `voice`/`model`, precedence flag > env > file > default. [M]
- `speak voices`: picker grouped by language, space plays a sample, enter saves; plain list off a
  TTY. Driven through a pty: preview, 3×j, enter wrote `voice = "af_nicole"`. [M]
- `speak models` list/download/rm. Pinned URLs + SHA-256; download to `.part`, resume with an
  HTTP range request (206 through GitHub's redirect), verify, rename. A corrupt part is deleted.
  The owner's existing files are used as-is: verified once, then remembered by size+mtime in
  `~/Library/Caches/speak/verified` (`~/.cache/speak` on Linux). Best installed model is the
  default. `SPEAK_NO_DOWNLOAD=1` disables downloads. [M]
- Fallback: model missing/corrupt/failing to load, or espeak-ng missing for a non-English voice →
  `/usr/bin/say` (macOS) or `espeak-ng`/`spd-say` (Linux), one-line note, exit 0; exit 3 only if
  that fails too. macOS paths [M]; Linux espeak-ng `-w` path [M] in the container, `spd-say` [I].
- espeak-ng lookup: `<exe>/../libexec/speak/espeak-ng` (+ data beside it, symlinks resolved) →
  `$SPEAK_ESPEAK` → `PATH`. Unit-tested and exercised end to end with a hard-linked binary. [M]

## Tests

56 tests: 43 unit (lexicon parsing/matching incl. speak.py quirks, chunking, config precedence,
npz/vocab, normalisation, espeak punctuation handling, misaki conversions, WAV, trim), 11 CLI,
2 regression. Model-dependent tests use `$SPEAK_TEST_MODELS` read-only via symlinks and skip
without it; all env and paths are redirected to temp dirs. [M]

Regression: `--g2p espeak` matches kokoro-onnx's saved phonemes/batches/tokens on 21/21 corpus
lines; audio of the KruAPI sentence matches within 1 LSB on macOS (176,640 samples). [M]
Extra differential runs against the Python reference (not in the suite): 36/36 stress lines
(multi-line, nested punctuation) in kokoro-onnx mode, Spanish and French; English unknown-word
fallback identical for 26 word/dialect pairs. [M]

## Things worth knowing

- **The spike's punctuation handling was a line-for-line port of phonemizer (GPL-3.0).** It is
  rewritten here from the observed behaviour (a per-line algorithm, no mark stack), then checked
  against kokoro-onnx: 21/21 corpus + 36/36 stress lines in three modes. [M]
- **Kokoro's audio isn't bit-identical across platforms.** Same tokens on Linux arm64 give
  correlation 0.998 with the macOS reference (max deviation ~9% of full scale). The audio test is
  strict on macOS arm64 only. Likely cause: platform differences in ONNX Runtime (e.g. the
  decoder's noise source using libc++ vs libstdc++ RNG distributions) [I].
- **Spaced capitals.** The owner's lexicon writes `crew A P I`; misaki reads a lone `A` as the
  article and `I` as the pronoun, so runs of single capitals are joined (`A P I` → `API`). [M]
- **Non-English voices now get misaki's `EspeakG2P` conversion** (what Kokoro was trained with, per
  `kokoro/pipeline.py`), not speak.py's raw espeak IPA. Not listened to. [I]
- **Japanese and Mandarin via espeak-ng are poor** (kanji read as "Chinese letter"), as in
  speak.py. Proper support needs misaki's ja/zh G2P. [M]
- **misaki-rs declares an unused dependency**, `language-tokenizer` (WTFPL, plus BSD-3-Clause
  `waken_snowball`): compiled, never called. Everything else in the tree is MIT/Apache-2.0/ISC/BSD/
  Zlib/Unicode/CDLA-Permissive-2.0 (webpki-roots). [M]
- **Model hashes**: the kokoro-onnx release publishes no digests. fp32/voices hashes come from the
  owner's existing download, int8 from a download today; sizes match the release API. [M]
- **Downloads have no stall timeout** (connect 20 s, first response 60 s, body unbounded). GitHub's
  CDN dropped to ~30–70 KB/s during testing. Two processes downloading at once corrupt the shared
  `.part`; the checksum catches it and both fall back. [M]/[I]
- **ALSA noise** on headless Linux when playing (not `-o`) is still printed by ALSA. [I, from spike]
